# 交付目录与旧产物迁移

工作区根目录以 `output/` 放正式交付，以 `tmp/` 放下载、清单、渲染、核验和旧副本；临时文件清理后 `tmp/` 可以不存在。每类费用的交付汇入 `output/YYYYMMDD_类型名称_汇总金额/`，其中金额不加“元”；该文件夹内放原始附件目录、同名证明材料 PDF、独立信息概要页 PDF，研发物料另放采购申请单 XLSX/PDF。跨类型共用附录可留在 `output/` 顶层。原始附件目录只放按 `序号_费用名称_材料类型名称.扩展名` 命名的原始附件，不放 `tmp/`、`downloads/`、`manifest.json` 或 QA 文件。运行 Python 工具时设置 `PYTHONDONTWRITEBYTECODE=1`，避免在脚本目录生成新的 `__pycache__`。

## 迁移旧目录时

1. **只读盘点**：列出根目录、`output/` 和各原始附件文件夹中的 PDF、XLSX、附件、`tmp/`、清单和 QA 文件；记录数量及目标路径。若目标已有同名文件，先比较哈希，不覆盖、不合并不明来源的内容。
2. **核对边界**：在 Windows 上先解析源和目标的绝对路径，确认都在本次工作区根目录内；不得对未验证的变量路径执行递归移动或删除。
3. **先迁临时文件**：将旧原始附件文件夹里的 `tmp/` 或其他中间文件移至根目录 `tmp/<批次名>/`，保留原有清单和下载层级。为每个类型创建 `output/YYYYMMDD_类型名称_汇总金额/`，再将只剩正式附件的文件夹、同批证明材料 PDF、信息概要页 PDF 和适用的采购申请单 XLSX/PDF 一起移入。保留各文件原名，不能覆盖目标。跨类型附录保留在 `output/` 顶层。
4. **被占用的正式文件**：不要强制结束 WPS、Excel 或 PDF 阅读器。可先复制到对应类型文件夹并校验源、目标 SHA-256 相同；请求用户关闭占用窗口。解锁后把旧位置的副本移至 `tmp/relocated-root-backup/` 暂存，不直接删除。若仍被占用，报告剩余旧副本并停止该项清理。
5. **缺失的原始附件文件夹**：仅当本批经过校验的 manifest 与稳定下载材料仍在 `tmp/` 时，先运行 `validate_manifest.py --materials`，再以 `export_original_attachments.py --dry-run` 核对文件名与数量，最后导出到一个不存在或空的 `output/YYYYMMDD_类型名称_汇总金额/<批次名>/`。不可从证明材料 PDF 反向截取附件来冒充原件。
6. **验收**：运行 `scripts/audit_output_layout.py --root <工作区根目录>`。再按 manifest 核对各类型附件数、记录数和金额，检查 PDF/XLSX 的内容与 A4 页面。`tmp/` 及其中备份只有得到用户明确确认才可删除。

迁移只是修正本地交付路径，不改变飞书记录或报销状态；飞书写回仍需遵守独立确认与逐条回读规则。
