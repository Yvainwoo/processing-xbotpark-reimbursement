# 交付目录迁移与清理

当前交付结构见 [SKILL.md](../SKILL.md#交付位置与名称)。本页只用于迁移旧布局、处理占用文件和清理临时资料。根目录 `tmp/` 可在用户确认清理后不存在；下一批处理时再创建。

## 迁移旧产物

1. 只读盘点源文件、目标位置和数量，核对本批日期、类型及金额。若目标已有同名文件，先比较哈希并查明归属，不覆盖。
2. 在 Windows 上解析源、目标的绝对路径；移动目录前确认它们都在预期工作区内。先把旧附件目录中的 `tmp/`、清单和 QA 材料移到根目录 `tmp/<批次名>/`。
3. 为每类建立 `output/YYYYMMDD_类型_汇总金额/`，移入该类原始附件目录、证明材料 PDF 和信息概要页 PDF。文件本身不改名。本批共用的采购申请单 XLSX/PDF 及跨类型预算附录放在 `output/` 顶层。旧采购申请单若只包含某一类型，不能仅靠移动文件当作本批汇总单；应按完整本批清单重新核对并制作，避免遗漏或同名覆盖。
4. 移动后核对文件数与 SHA-256，并运行 `audit_output_layout.py --root <工作区>`。该脚本检查目录命名、配套文件和临时文件隔离；清单金额与 PDF 内容仍要按本批清单核验。

## 特殊情况

- **文件被占用**：不强行关闭 WPS、Excel 或阅读器。可先复制到新位置并比对 SHA-256；用户关闭旧文件后，再把旧副本移到 `tmp/relocated-root-backup/`。若仍无法移动，报告具体路径。
- **原始附件目录缺失**：仅当经过校验的清单和稳定下载材料仍在 `tmp/` 时，先用 `validate_manifest.py --materials` 核对，再用 `export_original_attachments.py --dry-run` 检查名称与数量，最后导出到新的空目录。不能从展示 PDF 截图冒充原件。
- **清理 `tmp/`**：列明准确路径及其中的下载材料、清单、核验结果和旧副本；得到用户对本批清理的明确确认后才删除。写回状态的确认不能代替清理确认。移动交付物或清理本地目录不会改变飞书记录状态。
