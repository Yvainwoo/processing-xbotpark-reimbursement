#  证明材料PDF 排版规则

生成或修改 PDF 前必须使用 `pdf` 技能；首次 PDF 编写操作前必须立即运行该技能要求的产物启动标记。

## 排版

- A4 纸张，每条报销记录单独一页，页边距 10 mm。
- 页眉左侧为费用名称，右侧为金额；弱化的第二行仅显示“<n>    <费用类型>”。若字段映射提供 `sequence`，`<n>` 必须为多维表格“序号”字段的原始值，不得按 PDF 页码重编号。
- 上方区域为发票，下方左侧为订单凭证，右侧为付款凭证。
- 内边距 4 mm，使用浅灰边框。必须保持原始比例，不得裁剪凭证。
- 使用当前环境中可显示中文的字体。没有合适字体时，先解决字体问题再生成面向用户的 PDF。
- 只有用户同意纳入时才可显示缺失凭证；在对应区域以灰色文字展示用户给出的原因。

## 质量关卡

生成后重新打开 PDF，检查页数是否符合预期，使用 Poppler 将每一页渲染为 PNG，并进行视觉检查。交付前修正页眉截断、本应有内容却为空的区域、乱码、重叠和无法阅读的凭证。

为减少等待时间且不降低检查覆盖率，先一次性渲染所有页面，再将每 4 页合成为联系表进行总览检查；联系表发现问题时才单独以高分辨率检查对应页。还应以 PDF 文本或结构读取逐页比对页眉中的序号、费用名称、金额和类型是否与清单一致。不得只抽查部分页面。

PDF 是凭证的展示件，不是原始归档。必须保留每一份下载的原始文件。

多类型交付时，将每类的 `manifest`（根目录 `tmp/`）、`evidence_pdf` 和 `summary_pdf`（各自的 `output/YYYYMMDD_类型名称_汇总金额/`）、`qa_dir`（根目录 `tmp/`）写入同一个 UTF-8 JSON 数组，再一次调用：

```powershell
python scripts/verify_delivery.py --jobs-json '<任务 tmp>/delivery-jobs.json' --render
```

脚本会逐页核对清单与 PDF 文本、页数、A4 尺寸和概要页内容，并在 `qa_dir` 生成联系表。仍须人工看完所有联系表；仅对异常页做单页高分辨率复查。已通过的页无须反复渲染。
