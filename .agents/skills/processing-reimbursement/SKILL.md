# 处理报销

以用户给的飞书多维表格为唯一数据来源。脚本位于本 skill 的 `scripts/`，工作数据位于用户指定工作区的 `tmp/` 和 `output/`；运行命令时要分别使用正确的路径。
在 Windows 上运行本 skill 的 `.ps1` 时使用 PowerShell 7（`pwsh`）；不要用 Windows PowerShell 5.1 解析无 BOM 的 UTF-8 脚本。

## 开始前

从当前请求和已确认的会话信息确定：处理哪些费用类型或记录、交付根目录，以及是否纳入“已上报，未到账”。已有答案直接复用；用户说“当前目录”时使用当前工作区。默认只选“已审核”且报销状态为空的记录。只有范围或交付位置仍不明确时才询问。

## 工作流程

1. 按[多维表格读取与写回](references/base-workflow.md)解析 wiki 链接、核对表和字段，只读取一次完整分页数据。保存原始响应与字段映射到工作区 `tmp/`。
2. 用 `build_manifest.py` 建立本批[报销清单](references/manifest.md)，再用 `validate_manifest.py` 核对记录、金额和凭证。开始制件前一并检查信息概要页和采购申请单模板；如有占位或缺失信息，集中一次询问。凭证不全时列出具体记录，请用户决定排除还是附说明纳入。
3. 按清单下载并校验附件，再用 `export_original_attachments.py` 导出可读文件名的原始附件。下载、清单和核验文件只放在根目录 `tmp/`。
4. 逐类型制作[证明材料 PDF](references/evidence-pdf.md)和[信息概要页](references/summary-page.md)。概要页必须保留 PPT 模板的字体与版式，由 PowerPoint 打印为 A4 PDF，独立于证明材料。每种费用类型另按[采购申请单规则](references/procurement-application.md)筛选“实物图”有图的记录，制作采购申请单 XLSX，并从 Excel 模板打印 A4 PDF；不限于研发物料。
5. 批量运行 `verify_delivery.py` 核对 PDF 页数、A4、逐页字段和概要页内容，查看所有联系表；再运行 `audit_output_layout.py --root <工作区>` 检查交付目录。旧产物迁移或文件占用时按[目录迁移规则](references/output-layout.md)处理。
6. 资料核验通过后，列出本批交付清单，并运行 `writeback_manifest_status.py --dry-run`。向用户展示拟写回的记录 ID、条数、金额、目标字段“报销状态”及精确值“已上报，未到账”；**取得用户对本批写回的明确确认后**，才去掉 `--dry-run` 执行并逐条回读。只读核算、预览、单项产出或用户明确不写回时跳过。字段选项不符或预检异常时停止，按[写回状态](references/base-workflow.md#写回状态)处理。未经要求，不上传交付文件到飞书。
7. 写回完成或确定跳过后，列明根目录 `tmp/` 的准确路径及待清理内容；**取得用户对清理 `tmp/` 的单独明确确认后**才清理。写回确认不能代替清理确认，反之亦然；可在同一轮分别征求两项确认。
8. 最终回复列出实际交付清单、状态写回记录数与金额、预检和回读结果，以及 `tmp/` 的处理结果；未写回或未清理时说明原因，不能只说“已整理”。

## 交付位置与名称

`YYYYMMDD` 为制作日期，金额保持本批该类型的实际小数位。内部文件保留各自名称：

```text
output/
  YYYYMMDD_类型名称_汇总金额/
    YYYYMMDD_类型名称证明材料_汇总金额元/
      序号_费用名称_材料类型名称.扩展名
    YYYYMMDD_类型名称证明材料_汇总金额元.pdf
    信息概要页_类型名称_汇总金额元.pdf
    YYYYMMDD_采购申请单.xlsx  # 该类型有实物图的条目
    YYYYMMDD_采购申请单.pdf   # 同上
  跨类型共用附录.pdf          # 如有，留在 output/ 顶层
tmp/                          # 清单、下载、渲染和核验文件
```

原始附件的“序号”取多维表格字段原值，材料类型限“发票”“订单凭证”“付款凭证”；同类第 2 份起加 `_2`、`_3`。原始附件目录只放交付附件，不放 `tmp/` 或清单。用户明确确认本批交付完成后，才能清理根目录 `tmp/`。

## 交付确认清单

完成后逐类型列出可点击的 Markdown 文件链接、数量和金额，不以笼统的“已完成”代替。以下项目不适用时说明原因：

- [ ] 每种费用类型的原始附件文件夹路径、文件数，以及缺失或排除的记录。
- [ ] 每种费用类型的证明材料 PDF 路径、页数和金额。
- [ ] 每种费用类型独立的信息概要页 PDF 路径和金额。
- [ ] 每种费用类型有实物图条目的采购申请单 XLSX/PDF 路径、入选条数和金额；没有生成时说明原因。
- [ ] 跨类型共用附录等额外交付文件（如有）及本批合计金额。
- [ ] 飞书“报销状态”拟写回或已写回“已上报，未到账”的记录数与金额、预检和回读结果；未获写回确认时注明“待确认，未执行”。
- [ ] 根目录 `tmp/` 的路径及待清理内容、处理结果；未获单独清理确认时保留并注明“待确认，未清理”。
